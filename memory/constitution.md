# Принципи проєкту «Оформлено»

Ці правила важливіші за будь-яку окрему задачу. Якщо задача їм суперечить, змінюємо задачу.

1. **Оригінал недоторканний.** Сервіс ніколи не змінює завантажений файл; виправлення — лише в новій копії.
2. **Кожна помилка пояснена.** Звіт каже, яке правило порушено, де (номер абзацу або сторінки й перші слова) і що з цього каже методичка.
3. **Детерміновані правила, а не здогадки.** Перевірки описані в наборі правил і дають той самий результат для того самого файлу. ШІ допускається лише як підказка, ніколи як вердикт.
4. **Краще промовчати, ніж збрехати.** Якщо правило не можна перевірити надійно (наприклад, щось залежить від розбиття на сторінки), воно позначається як «перевірте вручну», а не як помилка.
5. **Методичка — це дані.** Нова методичка додається новим файлом правил, без змін коду.
6. **Приватність за замовчуванням.** Файли обробляються в пам'яті або тимчасовій теці й видаляються одразу після перевірки; текст робіт не логуємо.
7. **Українською.** Інтерфейс, звіти й повідомлення про помилки — українською.
8. **Перевіряється на реальних роботах.** Кожне правило має тест на справжньому .docx-файлі (з дозволу автора або згенерованому).
9. **Репозиторій приватний.** Репозиторій `oformleno` на GitHub створюється і лишається приватним (Private). Доступ — лише учасникам команди; зробити його публічним можна тільки за рішенням user.
10. **Codex за замовчуванням.** За рішенням user від 11.11.2026 роботу виконуємо в Codex без повторних запитань про вибір інструмента. Для дизайну використовуємо локальний MCP `/home/eugen/claude-talk-to-figma-mcp`. Це не скасовує меж погодженої задачі й підтверджень на контрольних точках.
11. **Дизайн — у Figma.** Усі макети, мокапи інтерфейсу, лендинг і візуали для демо робляться у Figma; посилання на файл Figma додається до відповідної задачі.
