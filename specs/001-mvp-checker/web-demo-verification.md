# T016 local web demo verification

`GATE: FAIL 17 (round 2 of 3)`

T016 implements the existing Streamlit architecture locally. No upstream gate
pass, deployment, GitHub CI, commit or push is claimed. The project Figma skill
adapts Taste to the checker/report interface; its marketing section-height,
picture, moment and container recipes do not replace the approved application.
The remaining gate findings and measured framework costs are retained below.

## Delivered behavior

- Ukrainian file choice/drop, validation, checking, reports, corrected-copy review,
  download and reset. Fixed EOM 2026 laboratory profile, matching the approved
  [upload design](https://www.figma.com/design/UscSNH67vwwxTFoaTj2f1h/Untitled?node-id=529-119)
  and [corrected-copy design](https://www.figma.com/design/UscSNH67vwwxTFoaTj2f1h/Untitled?node-id=529-522).
  Figma was inspected read-only through the selected local MCP, with no edits.
- Source files stay in the browser until Check. The component uses a one-shot
  Streamlit v2 trigger, then clears its input/File reference. Python consumes and
  clears the event, validates decoded size and DOCX, and processes it in memory.
  No original document bytes, source filename, filesystem upload or shared document
  cache is retained. Both public and serialized internal widget states were checked
  after processing; the source bytes/filename are absent.
- The same request prepares the initial report and, when fixes are reliable, a new
  corrected copy plus its repeated report. Only these results remain session-local.
  A zero-fix input does not retain the unchanged source as a download. The UI
  explains preparation during processing and offers “Переглянути виправлену копію”.
- Revealing the copy exposes only the verified corrected bytes for a DOCX Blob
  download named `Виправлена_копія.docx`. Primary actions precede secondary manual
  navigation. Reset clears the result and revokes the old Blob URL. Invalid new
  inputs clear stale output; copy preparation failure preserves the initial report
  with a safe explanation, without a download. Unexpected exceptions are not logged.
- The existing escaping HTML renderer supplies the findings and evidence. File
  names and status messages are text nodes. Required manual checks and residual
  errors remain visible after fixing; zero errors never claims full norm-control.
- Streamlit 1.67.0 and its dependencies are locked together. The wheel contains
  the component HTML/CSS/JS assets and no DOC/DOCX files. Telemetry, file watching
  and static serving are disabled. Loopback binding and default CORS/XSRF protection
  are retained. The framework native skip link is translated as accessible text.

## Verification

- `sh scripts/check.sh`: Ruff passed, **77 Python files formatted, 838 tests passed**
  on Python 3.12.3. The last UI-only changes also passed Node syntax validation and
  the browser checks. Document guard and `git diff --check` passed.
- **32 added pytest cases**: generated DOCX for all six fixable rules, byte-for-byte
  original preservation, no-fix/manual/check-only reports, inclusive 20 MiB decoded
  boundary, malformed payloads, sanitized exceptions, copy failure, stale output,
  result reset and independent sessions. Four cases run the actual Streamlit app
  using its component event protocol and inspect actual session/widget state.
  Targeted web/app/CLI verification passed 75 cases.
- A read-only Luna explorer examined the contracts and framework constraints.
  A read-only Sol reviewer found no remaining correctness issues, including the
  final scrolling/localization and verification-helper changes. The main agent
  owns all edits. No real student works were used.
- The isolated browser harness generated by `scripts/verify_web_frontend.py` runs
  the real component JavaScript with real File/DataTransfer/FileReader/Blob APIs.
  It passed extension/size rejection before transmission, filename HTML escaping,
  exact source bytes, cleared input, before/after reports, residual R08 and manual
  evidence, reveal/reset events, SHA-256 equality of downloadable Blob bytes and
  revocation of the previous Blob URL. It uses actual precomputed `web.py` results
  as its adapter; it is not a claim of a browser-to-live-server upload/download run.
  AppTest separately covers the actual Streamlit callbacks and transport shape.
- Browser checks use unmodified Taste scripts, sequential headless Chromium runs,
  their own profiles and ten-minute timeouts. Live upload and component report
  captures cover desktop/tablet/mobile; the mobile page scrolls normally and
  shows the full content. Figma typography uses local Funnel when available,
  otherwise a system fallback; exact font fidelity is not claimed.
- Gate basics **PASS**: 320 px overflow, collisions, tap targets, heading order,
  visible/unobscured keyboard focus, accessible names and hidden content. Its
  320×640 walk has no findings/probe errors. The native skip link's actual DOM text
  was verified as Ukrainian. Framework wrappers cause the remaining placement
  warning; source-CSS focus lint is separate from the passing interactive checks.
- The standalone five-width layout script errored with
  `Cannot read properties of undefined (reading 'map')` on the live framework page;
  only its first capture exists. This is not counted as a completed layout pass.
  Separate screenshots cover 1440, 1024, 820, 768 and 390 px. The kit was not edited.

## Measured limitations

`perf.mjs` on the actual local app, three loads per width, reports **4 FAIL / 4 WARN**
across 1440/390. Both widths exceed the generic static-site JavaScript and font
budgets: **2231.8 KiB parsed JS** and **532.7 KiB fonts**, from Streamlit's framework
assets. Transfer is about **2.8 MiB**, with **70–71 requests**. These costs are
retained under the approved Streamlit architecture; no dependency files were
patched to evade checks. Document processing makes no external service calls.

Measured local FCP/LCP medians were **808/780 ms**, layout shift **0.080/0.000**,
and blocking time **93/77 ms** at 1440/390. No broken requests or WebGL contexts.
These are local interface measurements, not hosted guarantees or the separate
30-page DOCX speed benchmark T020. No physical-device result is claimed.

The 17 open gate findings include marketing-picture/moment/hero requirements,
framework wrapper/container and split geometry assumptions, and three static
framework focus-ring declarations. The actual controls' focus checks pass.
No waivers were added, no kit files changed, and no failed result is called PASS.

## Local reproduction and evidence

```bash
uv run --no-sync streamlit run app/streamlit_app.py
uv run --no-sync pytest tests/test_web.py tests/test_streamlit_app.py
uv run --no-sync python scripts/verify_web_frontend.py
```

Local preview is `http://127.0.0.1:8501`. The owned verification server is stopped
at teardown. Generated documents use temporary directories and are removed by the
generator; browser evidence stays under ignored `tmp/t016/`. No uploaded work is
needed for verification. The helper prints the generated HTML path; open it with
the installed Taste `shoot.mjs` to see its `FRONTEND: PASS` status.

The detailed live gate data/crops are in ignored `.taste-skill/gate.json` and
`.taste-skill/gate/`. Performance data is in `tmp/t016/perf.json`. The frontend
browser harness is `tmp/t016/frontend.html`. Its English QA status is verification
output outside the Ukrainian product UI.

[v2 component registration](https://docs.streamlit.io/develop/api-reference/custom-components/st.components.v2.component),
[one-shot triggers](https://docs.streamlit.io/develop/concepts/custom-components/components-v2/state-and-triggers),
[AppTest](https://docs.streamlit.io/develop/api-reference/app-testing/st.testing.v1.apptest).
