# T018: демо на 60 секунд

Показуємо прототип для лабораторних робіт кафедри ЕОМ НУ «Львівська
політехніка» за погодженим профілем 2026 року. Інших методичок у демо немає.
Документ цілком синтетичний, без студентських текстів чи персональних даних.

## Підготовка

```bash
uv run --no-sync python scripts/make_demo.py
```

Команда повідомляє тимчасову теку. Для відтворення в цьому checkout можна
передати **нову** теку, наприклад `tmp/pitch-demo`. Наявні артефакти не
перезаписуються. У теці є:

- `Демо_10_помилок.docx` — завантажити для живої перевірки.
- `Демо_виправлено.docx` — заздалегідь перевірена копія для порівняння.
- `before.html`, `after.html` — самодостатні звіти, які відкриваються без мережі.
- `before.json`, `after.json`, `manifest.json` — перевірені очікування й контрольні суми.

Перед пітчем відкрийте застосунок і дочекайтеся готовності; файл має бути
під рукою. На екрані вибрано «Звичайний текст», профіль ЕОМ і лабораторну роботу.
Цей сценарій потребує версії з T009a. Для локального показу:

```bash
uv run --no-sync streamlit run app/streamlit_app.py --server.address 127.0.0.1
```

Публічне посилання для показу після оновлення й окремої перевірки:
[oformleno.streamlit.app](https://oformleno.streamlit.app/).
[Окремий звіт розгортання](feedback-deployment-verification.md) фіксує стан
хмарної перевірки цього сценарію; локальні результати нижче не закривають
контрольну точку всього етапу.

## Що закладено у файл

| Місце / правило | Порушення | Кількість висновків | Автовиправлення |
| --- | --- | --- | --- |
| Секція 1, R01 | Ширина сторінки 190 мм замість 210 мм | 1 | Так |
| Секція 1, R02 | Ліве 20 мм, праве 20 мм, верхнє й нижнє 25 мм | 4 | Так |
| Абзац 1, R03 | Звичайний стиль Word, Calibri замість Times New Roman | 1 | Так |
| Абзац 1, R04 | 12 пт замість 14 пт | 1 | Так |
| Абзац 1, R05 | Одинарний інтервал замість полуторного | 1 | Так |
| «Вступ», R06 | Центрування замість вирівнювання по ширині | 1 | Так |
| Перший підпис рисунка, R08 | 14 пт замість 12 пт | 1 | Ні |
| **Разом** | **10 помилок; після виправлення — 1** | **10 → 1** | **9** |

Сім ручних пунктів ЕОМ лишаються до та після виправлення. Їх не зараховано
як помилки чи підтверджені порушення. Значення у звіті можуть містити
невеликі дробові частини через одиниці Word.

## Сценарій

| Час | Дія | Репліка |
| --- | --- | --- |
| 0–8 с | Екран завантаження, видно профіль і режим | «Оформлено перевіряє оформлення .docx. Зараз це прототип під одну кафедру — ЕОМ. Покажу лабораторну роботу з навмисними помилками.» |
| 8–18 с | Обрати `Демо_10_помилок.docx`, натиснути «Перевірити документ» | «Перший абзац написано звичайним стилем Word: Calibri, дванадцять пунктів, одинарний інтервал. Стилі кафедри для такої перевірки не потрібні.» |
| 18–29 с | Показати підсумок 10 помилок / 9 виправлень | «Сервіс знайшов десять помилок. Дев’ять можна виправити автоматично: формат сторінки, чотири поля, шрифт, розмір, інтервал і заголовок.» |
| 29–40 с | Показати R03 і цитату; за потреби R02 | «Тут видно номер абзацу, його початок, фактичне й потрібне значення та цитату з вимог. Можна зрозуміти, звідки взялося зауваження.» |
| 40–52 с | «Переглянути виправлену копію» → «Завантажити виправлену копію» | «Завантажую окрему виправлену копію. Оригінал залишається незмінним. Копію вже повторно перевірено: замість десяти помилок залишилася одна.» |
| 52–60 с | Показати R08 і посилання на ручні перевірки | «Підпис рисунка треба виправити окремо. Сім ручних пунктів теж залишаються: сервіс не видає часткову перевірку за повний нормоконтроль.» |

Репліки розраховані на приблизно два слова за секунду та дії
одночасно з поясненням. Це сценарій на 60 секунд, а не твердження про вже
записаний чи відрепетируваний ролик. Перед захистом потрібна репетиція з таймером.
Запасний відеозапис належить до T019; ці HTML-звіти його не замінюють.

## Перевірка підготовлених артефактів

17.11.2026 генератор і незалежна повторна перевірка відкритих DOCX дали
**10 → 1 помилку, 9 автовиправлень, 7 → 7 ручних пунктів**. Збережено текст,
таблиці й оригінальні байти; виправляється нова копія. Тести також перевіряють
відмову перезаписувати наявні артефакти. Живий хмарний показ, реальне
відкриття копії у Word та незалежна точність на нових роботах цим не доведені.
